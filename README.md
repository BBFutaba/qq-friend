# QQ 群友

一个在你自己电脑上运行的 QQ 群聊伙伴。它通过 OneBot 11 接入 QQ。观察员 agent 先判断要不要接话，再由三个可切换的人格之一回复：GPT（本机 Codex）、Claude（Claude Agent SDK）或 DeepSeek（DeepSeek Harness）。它会按来源整理群友记忆，每条记忆都要经过你在后台审核；主动开启的新话题先由独立 agent 审核，再由你在 QQ 私聊里批准。

> **部署请看 [DEPLOY.md](DEPLOY.md)**。这份指南也是写给 AI agent（Claude Code、Codex 等）的，可以让 agent 按步骤帮你部署。

## 它能做什么

- **自然接话**：防抖合并消息、冷却与预算检查，由观察员决定回复、等待或忽略；回复按标点拆成几条，像真人一样分开发送。
- **有来源的记忆**：成员事实、群事件、人格印象和短期话题分开保存，每条都能追溯到原始消息。agent 只能提出候选，经你批准才会进入上下文。
- **安全边界**：只处理你启用的群和私聊白名单；QQ 里不能修改配置、执行命令或编程。调试模式下所有回复只发到你的私聊。
- **主动话题双审**：新话题先经独立 agent 审核，再发到你的私聊等待「批准 / 拒绝」。
- **可选能力**：图片、语音、视频理解（本地 Whisper 转写，不上传）；用 Chrome 扩展从你已登录的哔哩哔哩 / X 页面里找话题。

## 需要准备

| 项目 | 说明 |
|---|---|
| Windows 10 / 11 | 启动脚本和媒体环境按 Windows 编写 |
| Node.js 24+ | 内置的 `node:sqlite` 需要 Node 24 |
| 一个机器人 QQ 号 | 建议用小号，登录在电脑版 QQ 上 |
| OneBot 11 实现 | NapCat、LLOneBot、SnowLuma 等，需开启 HTTP 服务和正向 WebSocket，并设置 Token，地址只能是本机 |
| 至少一个模型后端 | Codex CLI（ChatGPT 账号登录）或 Claude Code + Claude Agent SDK。DeepSeek Harness 可选。**不使用 API Key** |
| Python 3.11+（可选） | 只有图片 / 语音 / 视频理解需要 |

## 快速开始

```powershell
npm ci
node scripts/setup.js
```

1. 双击 **启动QQ群友.cmd**，浏览器会自动打开后台 `http://127.0.0.1:4891` 并登录（管理密钥在 `data/admin-token.txt`，不要发给别人）。
2. 打开「连接与环境」，填写 OneBot 地址和 Token，然后填写机器人 QQ、你自己的审批 QQ、私聊白名单，并添加群。
3. 打开「人格与模型」，检测可用模型，给启用群使用的人格写好设定。
4. 「总览」里的首次设置清单全部打勾后，点右上角「启动群友」。默认是调试模式，回复只会发到你的私聊。
5. 试用满意后，在「消息与调试」里关闭调试模式，回复才会真正发到群里。

停止服务：双击 **停止QQ群友.cmd**。检查环境：`node scripts/doctor.js`。

## 后台页面

- **总览**：首次设置清单、连接、调用预算、待审核事项。
- **群友与记忆**：同步群友、编辑画像；按状态 / 类型筛选记忆，支持批量通过或拒绝、查看来源和修改历史。
- **表情包管理**：群里出现过的每张图片（按内容去重）、出现次数和解读。可以改写解读，把反复出现的图批量标记为表情包，再把表情包加入机器人的表情库，写下什么时候用。
- **人格与模型**：三个独立人格的设定、模型和推理强度；每个群使用哪个人格；后台 agent 的模型。
- **主动话题**：频率、安静时段、候选、审核结果和人工审批。
- **消息与调试**：拆句规则、调试模式、预览工作台、最近消息和发送记录。
- **浏览器**：Chrome 扩展配对，以及读取到的内容。
- **用量**：各职责的调用次数、真实 token、失败与耗时，最终上下文预算。
- **连接与环境**：OneBot 连接、QQ 账号 / 白名单 / 群聊、参与频率与预算、媒体开关。

## 运行方式

普通群聊消息先经过防抖合并、冷却和预算检查，再由观察员挑选需要的上下文和记忆。每个群、人格和调试状态各自整理新消息；候选长期记忆在后台通过审核后才进入上下文。成员画像以你确认的内容为准。

- **按需记忆**：先按群、人格、调试分支、审核状态和有效期过滤，再按当前参与者、被提及的成员和关键词排序。观察员返回的 `memoryIds` 就是本次回复允许使用的记忆。
- **记忆更新**：记忆 agent 提出 `add / update / expire` 建议，在后台显示修改前后的内容。批准后记忆 ID 不变，来源和版本都保留。人工编辑过的记忆默认受保护，agent 不能改。
- **图片预读**：装好媒体环境、并开启图片或视频读取后，观察员判断前会先用观察员模型描述最新 3 条消息里的图片和视频。每条有媒体的消息多一次模型调用，计入每天的调用上限。描述存在这条消息上，之后的回合直接复用，不会再描述一次。失败时保留「未读取」占位，日志里记一条提示，观察员照常判断。
- **图片只看一次**：开启图片读取后，每张收到的图片都会按内容算 SHA-256 并记录出现次数，即使机器人没有回复。同一张图再次出现时，直接使用「表情包管理」里保存的解读，不再下载、解码或调用模型；你改写过的解读优先，模型不会覆盖。回复模型看到的是这段解读，不是图片像素。
- **机器人表情库**：加入表情库并启用的表情包，会以短编号（s1、s2…）连同使用场景提供给回复模型。模型可以选一个跟在文字后面发出，也可以只发表情包；编号以外的内容一律忽略。表情包用 OneBot 图片消息（base64）发送，和文字一样受停止、过期和「出现新消息就取消」的检查。调试模式下发到你的私聊。
- **字符预算**：「连接与环境」里的字符上限，约束应用实际发给模型的全部文字。超限时先去掉优先级低的资料，人格和权限说明不会被截断。
- **主动话题审批**：在你的 QQ 私聊回复

  ```text
  批准 12位审批编号
  拒绝 12位审批编号
  ```

  审批会绑定群、人格、文案、来源、调试状态和有效期；修改配置或内容后需要重新审核。私聊里只识别这两条指令。
- **发送安全**：发送结果不明时不会自动重试，也不会把失败的私聊改发到群里。

## Chrome 中的哔哩哔哩 / X（可选）

1. 在 Chrome 打开 `chrome://extensions`，开启开发者模式。
2. 点「加载已解压的扩展程序」，选择本项目的 **browser-extension** 文件夹。
3. 在后台「浏览器」页面获取配对令牌，复制到扩展弹窗并保存；后台和扩展两边都启用读取。

扩展只读取你打开的页面里已经显示出来的内容：每 30 分钟最多读 4 个标签页、提交 20 条内容。它不提取 Cookie，也不点赞、发帖、关注或读取私信。

## 媒体理解（可选）

运行 `node scripts/setup.js --media`，会安装固定版本的解码器和离线 Whisper base 模型，放在 `workspace/.venv`。图片经校验、缩放后交给模型；语音在本地转写；视频最多读取前 60 秒的声音和 3 张抽帧。媒体只从 QQ 的 HTTPS CDN 下载，图片上限 5 MiB、音视频上限 25 MiB。没装媒体环境时，模型会被告知「未读取」，不会编造内容。

venv 只隔离 Python 依赖，**不是系统沙箱**。模型没有 shell、文件编辑或安装包的工具。

## 开发与验证

```powershell
npm test                          # 内存数据库回归测试，不连接 QQ
node scripts/doctor.js            # 只读环境检查，列出缺什么、怎么补
node scripts/configure.js --show  # 查看当前账号与群聊设置
node scripts/probe-models.js      # 用极短的测试请求确认各人格的模型真的能用（计入用量）
node scripts/verify-onebot.js     # 服务运行时只读检查 QQ 账号与群成员读取
node scripts/qa-server.js         # 在 4892 端口启动合成数据后台，用来看界面，不能发 QQ
```

## 数据与隐私

所有运行数据都在 `data/`：数据库 `friend.sqlite`（含聊天记录和记忆）、群里图片的本地原图 `media-cache/`（最多约 400 张、300 MB，超出时先清理最久没出现且不是表情包的原图）、连接 Token、管理密钥。这个文件夹不进 Git，也不要分享给别人。备份时先停止服务，再复制整个 `data` 文件夹。
