# QQ 群友

一个在你自己电脑上运行的 QQ 群聊伙伴。它通过 OneBot 11 接入 QQ。观察员 agent 先判断要不要接话，再由三个可切换的人格之一回复：GPT（本机 Codex）、Claude（本地 SDK 或 API）或 DeepSeek（DeepSeek Harness）。它会按来源整理群友记忆，每条记忆都要经过你在后台审核；主动开启的新话题先由独立 agent 审核，再由你在 QQ 私聊里批准。

> **部署请看 [DEPLOY.md](DEPLOY.md)**。这份指南也是写给 AI agent（Claude Code、Codex 等）的，可以让 agent 按步骤帮你部署。

## 它能做什么

- **自然接话**：防抖合并消息、冷却与预算检查，由观察员决定回复、等待或忽略；回复按标点拆成几条，像真人一样分开发送。
- **有来源的记忆**：成员事实、群事件、人格印象和短期话题分开保存，每条都能追溯到原始消息。agent 只能提出候选，经你批准才会进入上下文。
- **安全边界**：只处理你启用的群和私聊白名单；QQ 里不能修改配置、执行命令或编程。调试模式下所有回复只发到你的私聊。
- **主动话题双审**：新话题先经独立 agent 审核，再发到你的私聊等待「批准 / 拒绝」。
- **可选能力**：图片、语音、视频理解（本地 Whisper 转写，不上传）；用 Chrome 扩展从你已登录的哔哩哔哩 / X 页面里找话题。

## 需要准备

| 项目 | 说明 |
|---|---|
| Windows 10 / 11 | 启动脚本和媒体环境按 Windows 编写 |
| Node.js 24+ | 内置的 `node:sqlite` 需要 Node 24 |
| 一个机器人 QQ 号 | 建议用小号，登录在电脑版 QQ 上 |
| OneBot 11 实现 | NapCat、LLOneBot、SnowLuma 等，需开启 HTTP 服务和正向 WebSocket，并设置 Token，地址只能是本机 |
| 至少一个模型后端 | Codex CLI（ChatGPT 账号登录）或 Claude Code + Claude Agent SDK，或 Claude API。DeepSeek Harness 可选。本地模式忽略环境变量 API Key；API 模式使用后台专门保存的密钥 |
| Python 3.11+（可选） | 只有图片 / 语音 / 视频理解需要 |

## 快速开始

```powershell
npm ci
node scripts/setup.js
```

1. 双击 **启动QQ群友.cmd**，浏览器会自动打开后台 `http://127.0.0.1:4891` 并登录（管理密钥在 `data/admin-token.txt`，不要发给别人）。
2. 打开「连接与环境」，填写 OneBot 地址和 Token，然后填写机器人 QQ、你自己的审批 QQ、私聊白名单，并添加群。
3. 打开「人格与模型」，检测可用模型，给启用群使用的人格写好设定。
4. 「总览」里的首次设置清单全部打勾后，点右上角「启动群友」。默认是调试模式，回复只会发到你的私聊。
5. 试用满意后，在「消息与调试」里关闭调试模式，回复才会真正发到群里。

停止服务：双击 **停止QQ群友.cmd**。检查环境：`node scripts/doctor.js`。

## 后台页面

- **总览**：首次设置清单、连接、调用预算、待审核事项。
- **群友与记忆**：同步群友、编辑画像；按状态 / 类型筛选记忆，支持批量通过或拒绝、查看来源和修改历史。
- **表情包管理**：群里出现过的每张图片（按内容去重）、出现次数和解读。可以改写解读，把反复出现的图批量标记为表情包，再把表情包加入机器人的表情库，写下什么时候用。
- **人格与模型**：三个独立人格的设定、模型和推理强度；每个群使用哪个人格；四个后台 agent 各自独立选择 GPT / Codex、Claude 或 DeepSeek 的模型与推理强度。
- **主动话题**：频率、安静时段、候选、审核结果和人工审批。
- **消息与调试**：拆句规则、调试模式、预览工作台、最近消息和发送记录。
- **浏览器**：Chrome 扩展配对，以及读取到的内容。
- **用量**：各职责的调用次数、真实 token、失败与耗时，最终上下文预算。
- **连接与环境**：OneBot 连接、QQ 账号 / 白名单 / 群聊、点名与观察员频率、参与频率与预算、媒体开关。

## 运行方式

普通群聊消息先经过合并、冷却和预算检查，再决定要不要接话。每个群、人格和调试状态各自整理新消息；候选长期记忆在后台通过审核后才进入上下文。成员画像以你确认的内容为准。

- **点名直接回复**（参考 [qq-bridge](https://github.com/Derpyu520/qq-bridge) 的唤醒规则）：私聊、被 @、回复机器人的消息、叫到「连接与环境 → 点名与观察员」里设置的名字或关键词时，直接生成回复，不再先问观察员。短的英文名字按整词匹配，「gpt」不会匹配「chatgpt」。白名单私聊像正常聊天一样逐条回复：不受冷却、每小时回复上限和观察员频率限制（仍会合并连续几条消息；每日模型调用预算照常生效）。
- **闲聊批量判断**：其余消息先攒成一批，安静 8 秒后再判断；像没说完的话（以逗号、「然后」「但是」等结尾）等 12 秒。观察员每个群最多每 15 秒、每小时 60 次判断一批（DeepSeek 长会话下每次很便宜），超出时推迟到下一个空档，不会丢弃；回复冷却期间来的消息也会在冷却结束后再判断。数值都可以在后台调整。
- **活跃度与对话模式**（参考 qq-bridge 的「积极性」和「参与度参考」）：「连接与环境」里可选活跃度：安静（只在很自然时接话）、正常（默认，能接就接，不必等点名）、活跃（不习惯性潜水，常插话）。观察员每次还会看到一行参与度：最近 1 小时你和群友各说了多少、近 5 分钟多热闹，以及一句建议（刚说过话就先听，群里热闹而你一直没说话就插一句）。机器人回复某人之后进入对话模式：和它聊天的人接着说时立刻判断，不受观察员间隔和每小时上限限制，冷却缩短到合并窗口；双方 120 秒内都没再说话、这段对话回复满 8 次、或观察员判断对话已经结束（道别、话题转走、不再理它）时退出。
- **不丢已写好的回复**：写回复期间群里有了新消息，回复照样发出，并引用它回答的那条消息；新消息随后再判断。只有超过回复有效期的才放弃。Claude API（Opus 5.5 总是先思考）偶尔整轮只有思考、没有文字，或说“要用工具”却没给出工具请求：这时不带工具重试一次，并补一句“请直接输出 JSON，不想接话就输出空文字”；回复模型给出空文字就记为“这次选择不接话”，不算错误。叫错工具名（比如 Anthropic 自己的 web_fetch）时，web_fetch 按 web_read 处理（照样过审核），其他名字会收到“只能用 web_search 或 web_read”的提示，不再整条作废。每条回复最多 12 轮工具查询。仍然失败时，错误里会写明停止原因、返回了哪些内容块和第几轮。
- **群里的其他机器人**：在「群友与记忆」点成员的「标记为机器人」，或在「连接与环境 → 群里的其他机器人」填 QQ 号。它们的消息照样作为上下文（发言人标为「机器人」），但 @ 或回复它也不会直接叫醒群友，只交给观察员判断；连续回应它们达到次数（默认 2 次，0 为从不回应）后，等真人说话才会再回应，两个机器人不会来回刷屏。机器人的消息不会顶掉或取消正在回复真人的消息，也不参与记忆整理。
- **观察员只看新消息**：每次只给观察员上次判断之后的新消息（最多 12 条），再加之前 4 条作为上下文，人格只给一段简介（「人格与模型」里可以单独填写，留空取人格设定的前 300 字）。完整人格只用于真正写回复的那一步。
- **紧凑消息表**：发给模型的聊天记录是一张表（ref、发言人、几分钟前、内容、回复的 ref），不带内部 ID 和时间戳；空字段省略，较早的长消息只保留开头和结尾。观察员用 ref（如 m3）指出需要的上下文，应用再映射回原消息。
- **分享卡片**：QQ 的小程序、新闻、音乐分享卡片（比如哔哩哔哩视频）会写成一行「[分享 来源：标题 — 简介 链接]」放进消息，模型、记忆整理和后台都能看到，不联网。合并转发显示为「[聊天记录]」，文件显示为「[文件 名称]」，不再是空消息。卡片里的文字去掉换行和方括号并限长（伪造不了图片或 @），分享人的 QQ 和昵称不读取，B 站链接去掉跟踪参数。纯文字的 B 站链接不会自动查标题：B 站公开接口会拒绝非浏览器的匿名请求。
- **聊天记录（合并转发）**：收到时通过 OneBot 的 `get_forward_msg` 读一次（参考 qq-bridge），记成简短文字：谁说了什么，最多约 20 条，只展开一层，图片和嵌套的聊天记录用占位符；观察员和回复模型看到的是这段文字，不再只有「[聊天记录]」。读不到时用卡片自带的前几条预览。可在「连接与环境 → 媒体」关闭。
- **不适内容过滤**：聊天记录的内容（或预览）先用内置词表检查，不调用模型。命中的聊天记录不保存内容，任何模型都看不到（只显示「[聊天记录：不适内容，已跳过]」）；如果它正是要回应的那条，直接回一句「不爱看这种」，同一个群 10 分钟最多一次，不经过观察员和回复模型。这句话和额外的屏蔽词可以在「媒体」里改，留空就只跳过不回应。
- **B站 / YouTube 链接（经 Wander）**：消息里有这两个网站的 HTTPS 链接（包括分享卡片里的链接，每条消息最多两个）时，交给本机的 Wander 读取。Wander 通过你登录的 Chrome 只读地看视频信息、字幕或帖子，用它自己的模型写一两句说明；这句说明以「〔链接 B站「标题」作者：…〕」接在消息后面，观察员和回复模型直接看到，不需要回复模型再联网查。同一个链接一天只读一次；说明命中不适内容词时不保存，只显示「〔链接：不适内容，已跳过〕」。回复会等正在读的链接最多 15 秒。在「连接与环境 → 本地 harness 路径」填 Wander 地址（默认 http://127.0.0.1:4893）和 Wander 的 linkToken；没填令牌或在「媒体」里关掉时不读取。X 的链接暂时不读（你的要求）；其他网站的链接仍由回复模型自己的 web_read 处理。
- **回复节奏与时间**：群里多数人一次只打几个字，模型自己写却总是一句二三十字的完整话。每条回复随机带一个长度倾向（约 35% 只给反应、45% 一句短话、20% 可以完整一点；被直接提问时总是放宽），再附上群里的当前时间（默认北京时间，可用环境变量 `QQ_FRIEND_TZ` 改），只在和话题有关时才用。两者都放在每次的资料里，不改动可缓存的系统说明。`node scripts/voice-stats.js --since 2026-10-22T12:00 --persona claude` 只读统计回复和群友消息的长度分布（不输出消息内容），用来验收：回复中位长度 ≤ 15 字、至少 30% 在 10 字以内。
- **观察员长会话（DeepSeek，可选）**：观察员选 DeepSeek Harness 时，可在「连接与环境 → 观察员长会话」打开：每个群保持一个会话，第一轮发正常快照，之后每轮只发新消息和新增或改动的记忆、画像，ref 在会话里接着编号。之前发过的内容走 DeepSeek 的前缀缓存。人格简介、观察员模型或机器人账号变了，到达轮数或上下文上限（默认 30 轮 / 40,000 token），或闲置一小时，都会换新会话；会话丢失时自动用完整快照重发一次。合成聊天实测 flash 模型每次未缓存输入约 200 token（单次调用约 530，Codex 观察员约 12,000），延迟约 1.4 秒。「用量」页对比长会话和单次调用的未缓存输入。DeepSeek 的真实 token（缓存命中 / 未命中）从 DeepSeek Harness 自己的会话投影读取，读不到时记为未知。
- **不带你的 Codex 记忆**：应用启动 Codex 时关闭了 Codex 自己的记忆功能，你个人的 Codex 记忆不会进入群聊调用（也省下每次约 3,900 个 token）。
- **表情包节奏**：默认至少隔 3 次回复、每小时最多 6 次才把表情库提供给回复模型。QQ 图片的文件名如果已经核对过等于图片内容的 MD5，再次出现时直接用保存的解读，连下载都省掉。

- **后台模型**：观察群聊默认使用 `gpt-6.1-sol / low`（轻量）；记忆整理、审核、发现可独立选择模型，旧配置原样保留。模型与强度以本机客户端检测结果为准。DeepSeek 仅支持文本，选作观察员时图片 / 视频预读使用 `gpt-6.1-sol / low`，计入同一调用预算。
- **按需记忆**：先按群、人格、调试分支、审核状态和有效期过滤，再按当前参与者、被提及的成员和关键词排序。观察员返回的 `memoryIds` 就是本次回复允许使用的记忆。
- **记忆跟着 QQ 号走**：在某个群里记下的关于某人的事实和人格印象，跟着这个 QQ 号出现在他所在的每个群（和他的白名单私聊）里；同一个事实在别的群再出现，会合并成同一条记忆。群事件、短期话题、你的私人兴趣，以及在私聊里得知的内容，仍只留在原来的群或私聊。私聊里得知的内容记在对方 QQ 号名下，攒够 4 条新消息就整理一次，只在这段私聊里使用，也不会改动他的群记忆；在「群友与记忆」顶部的选择框切到「私聊 · 昵称」审核。群友按 QQ 昵称显示（各群一样），群名片显示在旁边；「群友与记忆」里来自别的群的记忆会标出「来自 某群」。
- **记忆更新**：记忆 agent 提出 `add / update / expire` 建议，在后台显示修改前后的内容。批准后记忆 ID 不变，来源和版本都保留。人工编辑过的记忆默认受保护，agent 不能改。
- **图片预读**：装好媒体环境、并开启图片或视频读取后，观察员判断前会先用观察员模型描述最新 3 条消息里的图片和视频。每条有媒体的消息多一次模型调用，计入每天的调用上限。描述存在这条消息上，之后的回合直接复用，不会再描述一次。失败时保留「未读取」占位，日志里记一条提示，观察员照常判断。
- **图片只看一次**：开启图片读取后，每张收到的图片都会按内容算 SHA-256 并记录出现次数，即使机器人没有回复。同一张图再次出现时，直接使用「表情包管理」里保存的解读，不再下载、解码或调用模型；你改写过的解读优先，模型不会覆盖。回复模型看到的是这段解读，不是图片像素。
- **机器人表情库**：加入表情库并启用的表情包，会以短编号（s1、s2…）连同使用场景提供给回复模型。模型可以选一个跟在文字后面发出，也可以只发表情包；编号以外的内容一律忽略。表情包用 OneBot 图片消息（base64）发送，和文字一样受停止、过期和「出现新消息就取消」的检查。调试模式下发到你的私聊。
- **字符预算**：「连接与环境」里的字符上限，约束应用实际发给模型的全部文字。超限时先去掉优先级低的资料，人格和权限说明不会被截断。
- **主动话题审批**：在你的 QQ 私聊回复

  ```text
  批准 12位审批编号
  拒绝 12位审批编号
  ```

  审批会绑定群、人格、文案、来源、调试状态和有效期；修改配置或内容后需要重新审核。私聊里只识别这两条指令。
- **发送安全**：发送结果不明时不会自动重试，也不会把失败的私聊改发到群里。

## Chrome 中的哔哩哔哩 / X（可选）

1. 在 Chrome 打开 `chrome://extensions`，开启开发者模式。
2. 点「加载已解压的扩展程序」，选择本项目的 **browser-extension** 文件夹。
3. 在后台「浏览器」页面获取配对令牌，复制到扩展弹窗并保存；后台和扩展两边都启用读取。

扩展只读取你打开的页面里已经显示出来的内容：每 30 分钟最多读 4 个标签页、提交 20 条内容。它不提取 Cookie，也不点赞、发帖、关注或读取私信。

## 媒体理解（可选）

运行 `node scripts/setup.js --media`，会安装固定版本的解码器和离线 Whisper base 模型，放在 `workspace/.venv`。图片经校验、缩放后交给模型；语音在本地转写；视频最多读取前 60 秒的声音和 3 张抽帧。媒体只从 QQ 的 HTTPS CDN 下载，图片上限 5 MiB、音视频上限 25 MiB。没装媒体环境时，模型会被告知「未读取」，不会编造内容。

venv 只隔离 Python 依赖，**不是系统沙箱**。模型没有 shell、文件编辑或安装包的工具。

## 数据与隐私

所有运行数据都在 `data/`：数据库 `friend.sqlite`（含聊天记录和记忆）、群里图片的本地原图 `media-cache/`（最多约 400 张、300 MB，超出时先清理最久没出现且不是表情包的原图）、连接 Token、管理密钥。这个文件夹不进 Git，也不要分享给别人。备份时先停止服务，再复制整个 `data` 文件夹。

代码复用来源见 [docs/REUSE.md](docs/REUSE.md)，设计取舍见 [docs/PLAN.md](docs/PLAN.md)。

## Claude API 与提示词编排

在「Claude API」页面选择 Anthropic Messages 或 OpenAI 兼容 Chat Completions，填写 Base URL（含版本路径，例如 `https://api.anthropic.com/v1`）与密钥。密钥保存在本机 `data/connections.json`，状态和请求预览不返回密钥；更换地址或协议需重新填写对应密钥。不要把凭据发到聊天或提交到 Git。

再到「人格与模型」，为 Claude 人格或任意 Claude 后台角色选择 **API**，填写服务提供的完整模型 ID、推理强度及预设后保存。SDK 模型别名与 API 模型 ID 不保证相同；支持读取 API 模型目录，也支持目录不可用时手动输入。未选择 API 的角色仍使用本地 SDK。

提示词预设支持复制、删除、块排序与启停，支持 system / user / assistant、输入资料前后插入、任务范围（reply / observer / memory / auditor / discovery / perception / preview）及 `{{model}}`、`{{role}}` 宏。system 块集中放入系统区；示例消息位于资料前，资料后可放补充要求。预设还支持 max_tokens、temperature 或 top_p，以及停止词。推理强度会发送为 Anthropic `output_config.effort` 或兼容接口的 `reasoning_effort`；模型不支持时留空，不会静默降级或重试。

**提示词缓存**（「Claude API → 提示词缓存」，默认 1 小时）：工具定义、系统说明、人格和资料前的提示词块每次都相同，请求在它们后面放一个缓存断点，重复部分按缓存价读取；群聊资料始终在断点之后。回复的系统说明不再随“这次有没有表情包菜单”变化，以免缓存失效。工具查询的多轮请求再加一个随最新内容移动的 5 分钟断点，后一轮读取前一轮。只对 Anthropic Messages 接口生效；命中比例见「用量」。

「组装请求预览」使用当前编辑中的预设及合成文本，不读取群聊历史、不调用模型、不消耗 API 用量。实际聊天仍使用应用的任务指令、批准过的记忆及已有上下文筛选；新增提示词计入最终字符预算，超出时拒绝调用。任务/JSON 边界、主动话题双审和暂停状态不受提示词编排影响。

编排参考 [SillyTavern Prompt Manager](https://docs.sillytavern.app/usage/prompts/prompt-manager/)，接口参考 [Anthropic Messages](https://platform.claude.com/docs/en/api/messages/create) 和 [Chat Completions](https://developers.openai.com/api/reference/resources/chat)。这是本应用的预设格式，不直接导入 SillyTavern 预设或执行其宏脚本。API 参数兼容性与真实额度需以选定服务为准；自动测试使用模拟响应。


## API 聊天查询工具

「Claude API → 聊天查询工具」可持久开启或关闭自主查询。开启后，Claude API 的 reply / preview 任务可调用 web_search（Bing RSS 公开搜索）及 web_read（公开 HTTPS 页面文字）。观察员会把聊天相关的搜索、新闻核实和资料查询当作普通接话需求，不再仅因“要求查询”而拒绝。其他 provider 与记忆、审核、媒体理解任务不开放这些工具。工具审核使用独立的 tool_audit 任务，不接触私人记忆；审核缺失或失败不会执行工具。

搜索只发送模型提炼的公开关键词，不需要新增搜索 API 密钥。不能保证搜索结果相关、完整或最新；模型应阅读原文、给出来源，并在失败时说明未核实。网页不执行脚本，不使用登录 cookies，不访问文件、内网或 OneBot。每次 DNS 解析及重定向都会检查公网地址并固定连接 IP。

每批工具调用由后台“主动话题审核”所选模型在独立会话中审核，通过后自动执行。查询与原任务绑定，群友说“查一下”本身不是拒绝理由；无固定四次查询上限，整个 API 回合仍最多 75 秒。审核和后续模型请求计入每日调用预算。初始上下文遵守原输入预算；查询交互额外保留 16000 字符（总上限 64000），旧结果会保留来源并压缩，必要时移除完整的旧工具交互；成功回合累加各次 API 报告的 token 用量，缺失用量保持未知。最近活动只记录工具名与成功/失败，不记录查询词或网页正文。

“组装请求预览”始终不执行工具；“消息与调试”的模型回复预览会实际调用模型及已启用的查询工具，但不发送 QQ。查询只用于响应当前聊天；主动新话题仍走双审。

工具协议参考 [Anthropic 自定义工具](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools)。

普通聊天回复遇到标点导致的过多分条时，先在单条长度内合并；仍放不下则以无工具的 reply_repair 任务压缩一次。主动话题审批内容仍使用严格分条，不在审批后改变文本。
